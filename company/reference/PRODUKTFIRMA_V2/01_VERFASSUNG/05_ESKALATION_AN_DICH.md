# ESKALATION AN DICH

Damit du nicht mikromanagen musst und trotzdem nichts hinter deinem Rücken passiert. Die Firma fragt dich **nur** bei diesen Triggern. Alles andere entscheidet sie selbst.

---

## 1. Wann die Firma dich fragen MUSS

| Trigger | Beispiel |
|---|---|
| **Kosten über Schwelle** | neues kostenpflichtiges Tool/Abo, API mit laufenden Kosten, einmalig über der vereinbarten Grenze |
| **Irreversible Datenänderung** | Tabellen löschen, Daten migrieren ohne Rückweg, Produktivdaten überschreiben |
| **Neue externe Abhängigkeit** | neuer Connector, neue API, neuer Drittanbieter im Produktpfad |
| **Sichtbare UI-Änderung** | jedes Redesign / neue Oberfläche → kommt als **Visual Pitch** zur Absegnung |
| **USP-Berührung** | etwas würde den USP verändern oder verwässern |
| **Twin-Konflikt** | ein Twin würde durch die Lösung nachweislich überfordert |

**Schwelle Kosten:** lege deinen Wert fest (Vorschlag: alles über 20 €/Monat laufend oder 100 € einmalig). Trag ihn unten ein.

```
KOSTEN-SCHWELLE (vom Stakeholder gesetzt):
  laufend:   ____ € / Monat
  einmalig:  ____ €
```

---

## 2. Wann die Firma NICHT fragt

Architektur, Datenmodell-Details, Tool-Wahl innerhalb des Budgets, Code, Testverfahren, Reihenfolge der Umsetzung, Rollenbesetzung, interne Blocker. Das sind Fachentscheidungen — sie landen nicht bei dir, sondern werden gelöst und im Ergebnis bewiesen.

---

## 3. Entscheidungs-Vorlage (max. 5 Zeilen, knapp begründet)

So bekommst du jede Entscheidung — nie mehr Text:

```
ENTSCHEIDUNG NÖTIG · [IDEA-ID / Mission]
Was:            [eine Zeile]
Warum jetzt:    [eine Zeile]
Alternativen:   [A | B | nichts tun]
Empfehlung:     [eine Zeile, mit Grund]
Folgen bei Nein:[eine Zeile]
```

Du antwortest mit „A" / „B" / „nein" / „so nicht, ändere X". Mehr nicht nötig.

---

## 4. Visual-Pitch-Vorlage (UI)

Bei UI-Änderungen kommt **kein Text-Vorschlag**, sondern ein klickbares Mockup:

```
VISUAL PITCH · [Bereich, z.B. Auftrag anlegen]
Problem heute:  [eine Zeile, z.B. "13 Klicks, Nutzer verliert sich"]
Vorschlag:      [Link zu klickbarem HTML/Figma]
Twin-Check:     [welche Twins, was sagen sie]
Messbarer Gewinn:[z.B. "Auftrag in < 30 Sek statt > 2 Min"]
Deine Freigabe: [ ] ja  [ ] nein, ändere: ____
```

---

## 5. Rückmeldungs-Rhythmus

Pro Mission bekommst du:

- **Eingang:** IDEA-ID + verstandenes Ziel + erster Einschätzungstyp.
- **Konzept:** vervollständigte Idee + Varianten + Empfehlung + USP-Wirkung (+ Visual Pitch bei UI).
- **Entscheidung:** beschlossen / zurückgestellt / Forschung / begründet abgelehnt.
- **Live:** Produktionsbeweis + erfüllte Kriterien + Restrisiken + Wirkungskontrolle.

**Kein Schweigen, keine Zwischenberichte-Flut.** Eine Idee bleibt nie ohne Status. Aber du bekommst auch keine Berichts-Lawine — nur diese definierten Punkte.
