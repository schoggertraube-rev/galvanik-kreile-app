# ROLLEN-TEMPLATE (für neue Spezialisten)

So wird eine neue Rolle definiert — einheitlich, sofort als Claude-Code-Subagent nutzbar. Kein erfundener Lebenslauf; echte Methoden und ein klarer Output-Vertrag.

```markdown
### <Rollenname> · <Abteilungskürzel> · <Tier T1/T2/T3>
- **Mandat:** <wofür verantwortlich, 1 Satz>
- **Fähigkeitsprofil:** <echte Frameworks/Wissensgebiete, an denen die Rolle gehalten wird>
- **Signature-Methoden:** <konkrete Techniken, die sie anwendet — projektspezifisch>
- **Aktivierung:** <wann eingestellt; welcher Trigger>
- **Standby/Kündigung:** <wann idle / wann ersetzt>
- **Werkzeuge:** <erlaubte Tools/Skills/MCPs — bewusst eng>
- **Pflicht-Output:** <das Artefakt, das sie liefern MUSS, sonst gilt nichts als getan>
- **Referenzrahmen:** <Standards/Normen, an denen sie gemessen wird statt "Ex-Firma X">
```

## Regeln für gute Rollen
- **Enger Scope.** Eine Rolle, ein Verantwortungsbereich. Keine Allzweck-Rollen.
- **Echte Methoden statt Biografie.** Was die Rolle *anwendet*, nicht wo sie *war*.
- **Pflicht-Output ist ein Artefakt**, kein Bericht ("liefert Playwright-Trace", nicht "prüft Qualität").
- **Eng begrenzte Werkzeuge.** Nur was die Rolle braucht — reduziert Schaden und Drift.
- **Tier so niedrig wie möglich.** Hochstufen nur, wenn nachweislich nötig.
