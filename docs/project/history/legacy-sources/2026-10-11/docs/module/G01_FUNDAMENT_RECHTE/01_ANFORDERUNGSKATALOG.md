## Permission-Zuordnung V1

| PermissionKey | Serverseitig zu schützender Umfang |
|---|---|
| `perm_sys_toggles` | System-/Feature-Schalter lesen und ändern; nie Ersatz für `AdminAuthority` |
| `perm_sys_diag` | technische Diagnose lesen |
| `perm_sys_users` | Personen-/Rechteübersicht lesen; Änderungen zusätzlich nur mit `AdminAuthority` |
| `perm_data_csv` | fachliche Exporte auslösen |
| `perm_data_customers` | Kunden, Kontakte und Notizen anlegen oder ändern |
| `perm_data_orders` | Aufträge, KV, Rechnungs- und Zahlungsparameter anlegen oder ändern |
| `perm_op_status` | Auftrags-/Werkstattstatus und Warenausgang ändern |
| `perm_op_risk` | Risiko-/Warnungsdaten ändern |
| `perm_op_photos` | Fotos/Dokumente hinzufügen oder Originale abrufen |
| `perm_op_qa` | Qualitäts-/Prüfhandlungen bestätigen |
| `perm_view_leitstand` | Home, Werkstatt, Aufträge und Suche lesen |
| `perm_view_customers` | Kunden und Kontakte lesen |
| `perm_view_prices` | Preise, Rechnungen und Zahlungsinformationen lesen |

Bei einem Command mit mehreren Wirkungen müssen alle zugeordneten Rechte erfüllt sein. Rechnung ausstellen oder Zahlung bestätigen verlangt beispielsweise `perm_data_orders` **und** `perm_view_prices`; eine Rechteänderung verlangt unabhängig von allen PermissionKeys immer `AdminAuthority`.
